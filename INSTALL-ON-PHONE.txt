YJ Studios — install and use the website app

1. Open the published website over HTTPS. Opening `index.html` from a files app does not enable installation, Firebase sign-in, or uploads.
2. On Android, use the browser menu and choose **Install app** or **Add to Home screen**. Chrome and Samsung Internet can provide an app-style install on supported devices; some other browsers create a browser shortcut.
3. On iPhone or iPad, open the site in Safari, tap **Share**, then **Add to Home Screen**. On recent iOS/iPadOS versions, other browsers can also offer the Home Screen option in their share menu.
4. On Windows, Linux, and Chrome/Edge on macOS, choose the install icon in the address bar or **Install YJ Studios** in the browser menu. On macOS Sonoma or later, Safari provides **File → Add to Dock**. Firefox desktop does not provide manifest-based PWA installation; use Chrome or Edge for a separate app window.
5. The **Install App** button opens the browser prompt where available and shows device-specific instructions otherwise.

The site shell can open offline after it has been visited online once. In **Studio Work → Offline data settings**, you may opt in to Firestore's IndexedDB cache on a trusted personal device. Previously synchronized project metadata and pending metadata-only changes can then survive a refresh. The browser may still evict its storage; do not enable this on a shared device. The service worker itself does not cache private documents, auth responses, or media files. Audio/video playback, remote images, uploads, notifications, sign-in, and WhatsApp still need an internet connection.

The Studio Work upload workflow remains online-only: choose **+ Add Project**, sign in using the authorized Firebase account when prompted, select media and details, preview, then save as a draft or publish. Upload progress appears in the form. Metadata-only external-link projects can be queued offline after trusted-device storage is enabled; R2-backed publish/unpublish/delete actions require a connection. Firebase and the R2 Worker must be configured before uploads can succeed.

For supported offline workflows, conflict handling, pending-write behavior, and device test steps, see `OFFLINE_SETUP.md`.

Firebase setup is required first: enable the selected Authentication provider, add the website domain to Authorized domains, grant the Firebase UID its trusted custom claim from a trusted environment, deploy Firestore rules, and deploy/configure the Cloudflare R2 Worker. See `FIREBASE_SETUP.md` and `R2_SETUP.md` for exact commands and limitations.

Do not publish `admin-tools/`, backend credentials, or service-account keys with the site.
